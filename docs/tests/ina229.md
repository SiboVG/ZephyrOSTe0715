# INA229 bench

`app/apps/fprime_ina229_bench` runs fprime-ina229's `Ina229.Manager` on SPI1 against a
real INA229. Set up the wiring first ([SPI sensor benches](spi-sensors.md)); use the
same INA229 board as the library's FT232H bench.

## The measurement circuit

Connect the shunt and the bus as the board's documentation and the TI reference
circuit prescribe: the load current flows through the shunt between IN+ and IN−, and
VBUS senses the bus voltage (0 to 85 V). Keep the load circuit's ground common with
the TE0701 ground. Record in the as-run record:

- the shunt resistance and its tolerance (passed as `--shunt` and `--shunt-tolerance`);
- the expected maximum current (`--max-current`), which sets the current resolution;
- the load: supply voltage, load resistor or electronic load setting;
- the reference instruments and their uncertainty (`--ref-uncertainty`, % of reading).

The INA229's VS supply is 3.3 V from Pmod J1 (see the wiring warning); the bus voltage
is independent of it.

## Shell commands

| Command | What it does |
|---|---|
| `ina info` | Bench and library revisions, SPI settings, streaming state |
| `ina spi [hz [mode]]` | Show or change the SPI clock request and mode (not while streaming) |
| `ina id` | Read MANUFACTURER_ID and DEVICE_ID directly over SPI; PASS for 0x5449, die 0x229, and a low byte during the command byte |
| `ina reg <addr>` | Read one register directly over SPI. Reading DIAG_ALRT (0x0b) clears its conversion-ready flag |
| `ina wreg <addr> <value> [rst_delay_us]` | Write one 16-bit register over raw SPI and read it back. With `rst_delay_us` it first resets the device and waits. `write_rx` is what the INA229 clocked out during the write: the previous value when the frame arrived intact |
| `ina soak <n>` | n direct reads alternating MANUFACTURER_ID and DEVICE_ID, each checked, with transfer times |
| `ina init <shunt_ohm> <max_current_a> [narrow] [tempcomp] [mode M] [conv B S T] [avg A] [tempco PPM] [delay STEPS]` | Initialize through the manager's `configure` port. Defaults: wide range, continuous conversion of all channels (mode 15), 1052 µs per conversion (code 5) and 16 averages (code 2): about 50 ms per result |
| `ina read [count] [period_ms]` | Readings through the manager's `read` port (CSV); a not-ready result is polled for up to 15 s |
| `ina timing [n]` | Duration of n successful manager reads, and of not-ready answers |
| `ina stream start <period_ms> [rows]`, `ina stream stop`, `ina stream status` | Readings from the 100 Hz rate group, printed as rows |
| `ina cmd <command> [args]` | Send an `Ina229.Manager` command through the command dispatcher: `init` (arguments as `ina init`), `adc <mode> <bus> <shunt> <temp> <avg>`, `trigger`, `stop`, `reset-acc`, `alert <bits>`, `threshold <addr> <raw>`, `snapshot`, `report`, `clear-throttle` |
| `ina tlm [on\|off]` | Printing of telemetry on the console |

A reading is one CSV row, for example:

```text
INA_HEADER,time_ms,status,valid,bus_V,shunt_V,temp_C,current_A,power_W,energy_J,charge_C,diag
INA_ROW,52310,OK,0x7f,12.001221,0.014998125,26.1094,0.999875,11.999721,0.000000,0.000000,0x0001
```

`valid` holds the library's validity bits (bus, shunt, temperature, current, power,
energy, charge); `diag` is DIAG_ALRT as the read found it.

## Procedure

`sensor_bench.py ina229` runs these steps; the numbers are those of the
[test case specifications](../verification/test-cases.md).

### TC-13 SPI1 link

1. `ina id`: identity PASS.
2. `ina soak` with 20000 transfers at every SCLK of the clock table in mode 3: no
   wrong value, no non-zero byte during the command byte, no driver error.
3. `ina wreg 0x01` with six values (0x0b6a, 0xfb6b, 0x5555, 0xaaaa, 0x0000, 0xfb68) at
   every SCLK in mode 3: each value read back, and each write frame returned the
   previous value. The script then repeats the writes in mode 1 at 1.116 MHz and
   records the result as INFO, to show whether the mode 1 defect is still there.

Reads alone do not show a wrong SPI mode: in modes 1 and 2 steps 1 and 2 pass while
some writes are lost ([Known issues](../known-issues.md)). The three steps verify the
chip select and the SPI mode by function
(`TE-SPI-002`, `TE-SPI-003`); no waveform is captured. The waveform part of the
library's INA-HIL-001 stays open for the flight hardware.

### TC-14 The F Prime manager

1. `ina init <shunt> <max_current>`: `status=OK`.
2. `ina read 20 0`: 20 rows, all `OK`, valid mask `0x7f`, die temperature 5 to 50 °C,
   current equal to shunt voltage divided by the shunt resistance (within 1 %), power
   equal to bus voltage times current (within the data sheet's 0.5 %).
3. `ina cmd report` and `ina cmd snapshot`: response OK, telemetry printed.
4. `ina cmd init 0 5` (zero shunt): VALIDATION_ERROR, and the manager's `Errors`
   telemetry does not change (INA-009).
5. `ina cmd alert 0x8000`, then `ina reg 0x0b`: ALATCH set, MEMSTAT still 1 (the
   library's read-modify-write keeps MEMSTAT on silicon, INA-HIL-004). Restored
   with `ina cmd alert 0x0000`.
6. `ina cmd reset-acc`: response OK.
7. `ina timing 200`: 200 reads, none failed. Record the duration: it is how long the
   manager's mutex is held per read (INA-HIL-006).
8. `ina stream start 100 20`: 20 rows at 10 Hz from the rate group, no failures.

### TC-15 Readings against reference instruments (interactive)

With a steady load, compare 50 readings with the reference meters. Pass limits: the
data sheet's worst-case errors (SLYS023A 6.5: VBUS gain 0.05 % and offset 2.5 mV;
shunt gain 0.05 % and offset 1 µV) plus the shunt tolerance and the reference
uncertainty; the die temperature within 2 °C of a thermometer next to the INA229.
Then reverse the load current and repeat the current comparison (INA-HIL-002, one
operating point per run; repeat the run for more points and for `narrow`).

### TC-16 Faults (interactive)

1. Disconnect MISO: `ina id` fails and no reading is reported valid.
2. Reconnect MISO: readings recover without reinitialization; the manager logs
   `Recovered`.
3. Remove the INA229's supply: no reading is reported valid.
4. Restore the supply without reinitializing and record what the manager reports.
   After a power loss the INA229 is back in its reset state. On 2026-10-04 the
   manager then reported every reading valid, with the current 10 % low and the
   energy restarted from zero ([as-run record](../verification/as-run-ina229-2026-10-04.md#findings-for-the-libraries)).
   Compare the current with shunt voltage / shunt resistance and note whether the
   library flags the reset.
5. `ina init`: valid readings again.
