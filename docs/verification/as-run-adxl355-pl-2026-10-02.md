# ADXL355 on the PL's clock and pulse: as-run record 2026-10-02

This record assesses the first run of [TC-22](test-cases.md#tc-22-adxl355-on-the-pls-external-clock-and-synchronization-pulse):
the ADXL355 in its flight synchronization mode, on the 1.024 MHz clock and 4 kHz
pulse of the [cubespec-pl](https://github.com/SiboVG/cubespec-pl) bitstream, with the
synchronized application triggered by the PL's sync interrupt. It verifies `TE-ADXL-007`
and `TE-ADXL-008`, and `TE-ADXL-004` in the synchronized mode. The image, the library
and the bitstream were built from committed sources for the assessed run.

The development runs found two things before TC-22 existed: a wrong ground on the level
translator, and a sensor that freezes when its clock stops. The freeze led to
fprime-adxl355's `FROZEN_DATA`, see
[Findings for the libraries](#findings-for-the-libraries).

### What the steps show

- **Frames in phase with the pulse (TE-ADXL-007).** The sensor sets DATA_RDY within a
  16 µs window around the sync instant. The window stayed put while each restart moved
  the pulse train against the sensor's own sample timing, so the sensor follows the
  pulse. A read 2 µs after the instant already finds the new sample. The frame
  timestamp is the instant itself, from the PL time base, so frames line up across
  sensors and with the PS clock (step 2).
- **Start-up (TE-ADXL-007).** Initializing before the clock starts, as the ACC board
  design notes require, works. After the 0.5 s wait, \|a\| of every one of the 20000
  samples lies within 4.2 mg, so no sample is corrupted, the first ones included.
- **A stopped clock (TE-ADXL-008).** The sensor's logic runs on EXT_CLK, so STATUS
  reads stop clearing DATA_RDY. What the sensor then reports depends on where in the
  period the clock stops. With a sample unread, DATA_RDY stays set and the library
  reports `FROZEN_DATA` from the ninth read (step 9; run E's step 11). With the last
  sample read, DATA_RDY stays clear and every read is `STALE_DATA` (this run's step
  11). After `FROZEN_REPEAT_LIMIT` reads at most, no frame passes as valid.
- **Stopped pulses (TE-ADXL-008).** Without pulses there are no triggers; the timing
  thread's 100 ms waits time out and the deployment sees it (step 12). The sensor
  itself keeps converting.
